# 自动配乐

由 **yuyuyu-a** 独立维护的 Windows 自动配乐软件。本仓库的 `main` 分支和正式安装包均包含剧情辅助、可配置 API、多层曲库扫描和自定义配乐上限。

## 下载

从 [自动配乐下载页](https://github.com/yuyuyu-a/auto-bgm/releases/latest) 下载
`auto-bgm-setup-1.0.7.exe`，安装后运行“自动配乐”。不是只下载源码 ZIP。
安装包内含 FFmpeg、faster-whisper small 和 YAMNet，本地处理不需要另装 Python 或下载模型。
剧情辅助需要在“设置 → 剧情 API”填写自己的服务地址、模型和密钥；不附带任何私人密钥或曲库。
独立版只检查本仓库的新版本，不会自动更新回原项目。

本项目基于 [crazyzhang277/short-drama-bgm](https://github.com/crazyzhang277/short-drama-bgm)
开发，保留其 MIT 版权及第三方许可。独立版使用单独的安装身份和本机设置，
可与原软件并存；首次运行需重新选择素材目录和配置 API。

一款面向短剧剪辑与内容运营的本地 Windows 桌面工具。选择视频目录、按情绪整理的背景音乐库和输出目录后，应用会批量生成混合原视频声音与 BGM 的成片，并提供音频、选曲时间表和转录材料供检查。

应用在本机处理素材。默认自动选曲依赖音乐分类与转录文本规则；本地二创版可选开启“剧情辅助”，由用户配置的第三方接口结合剧本和实际对白规划音乐。结果均需要人工试听确认。

- 规则模式与剧情辅助均生效，不增加剧情 API 请求。时长换曲优先于每集片段数量上限，保留明确剧情留白、场景变化与片尾定格。
- 已有正常成片不会自动改写；需要应用新时长时，使用单集重新生成或关闭“跳过已完成”后运行。继续保留下面的旧版意外留白修复。

## v1.0.6：旧版中性留白自动重配（2026-11-17）

- 修复旧版“中性留白”被标记为已完成、升级后仍直接跳过的问题。更新后点击“开始批次”或“继续未完成”，已选择输出中的旧版意外留白会自动按新版规则重新生成。

- 在出问题的电脑安装此版本后，需要再次运行该批次；软件更新本身不会后台改写成片。

## v1.0.5：相近曲风与抒情替代（2026-11-16）

- 对应曲风不足时，先找相近分类，再找兼容中性音乐，例如浪漫用温情、浪漫／温情缺失时用抒情、紧张用悬疑、伤感用忧郁。原曲风仍优先，抒情优先于励志和中性替代；替代依据会写入选曲原因并标记待试听，不会仅为补数使用相反情绪。
- 抒情分类支持 `曲库/抒情/`、`曲库/音乐合集/03_抒情/第二辑/` 等目录，按分类名称识别，不代表自动听音识别曲风；纯音乐筛选要求保持不变。
- 没有明确情绪、也没有默认分类时，从已筛选曲库选择较克制的候选；完全没有合适曲目时明确报错，不再将规则配乐输出为“中性留白”。
- 相似度来自目录风格标签与已有强度设置，不是新增的音频情绪识别。纯音乐筛选、禁用和同名去重继续生效；剧本明确要求的“剧情留白”及片尾定格仍保留。
- 规则模式下，同一首音乐跨情绪段连续使用时保持连续播放，不会从头重播或与自身交叉淡化。
- 此版本保留旧结果，需要手动重配；1.0.6 已加入运行批次时自动修复旧版意外留白的处理。

## v1.0.3：同名音乐去重（2026-11-15）

- 扫描整个曲库及所有子目录后，完整文件名相同的音乐只分析、使用一份，忽略文件名大小写。例如 `theme.mp3` 和 `THEME.MP3` 视为同一首；`theme.wav` 和 `theme (1).mp3` 不会合并。
- 按路径的自然顺序固定选一份，在解码、人声识别之前跳过其他同名副本；不比较这些副本的音频内容，也不删除、移动或修改原文件。
- 同名曲目放在多个情绪目录时保留这些分类，但共享同一份音乐和筛选结果；不会当作多首凑满每集曲目下限。界面显示跳过的副本数量及实际使用的文件。
- 所选文件继续使用已有缓存。文件变化后需要重新确认或分析；若所选文件损坏、疑似有人声或被禁用，不会通过另一个同名副本绕过筛选。旧成片需要重新生成才能应用新规则。

安装版可在“关于”页检查更新；1.0.2 也会在空闲检查到更新时显示提醒。覆盖安装保留本机 API 配置与素材，不需要重新下载模型。

## v1.0.0：剧情辅助配乐与独立发布（2026-11-14）

- 在工作台开启“剧情辅助”，选择对应剧本或分镜；自动启用本地语音转录，不必另备字幕。
- 支持 TXT、Markdown、JSON 和 Word DOCX，单集最多 80,000 字符。单视频可直接选文件；
  批量视频请选择目录，例如 `episode-01.mp4` 对应 `episode-01.docx` 或 `episode-01.script.md`。
  同集多个版本或缺失文件会明确提示，不会串用其他集剧本。
- 在“设置 → 剧情 API”保存 HTTPS 地址、模型和密钥。地址会规范到 `/v1`；
  使用兼容的 `GET /models` 与 `POST /chat/completions`，可以获取模型和检测连接。
  密钥仅在主进程中使用，由系统加密保存，不写入源码、浏览器存储或批次日志。
- 开启即授权向该服务发送选定剧本、实际对白及时间、镜头切点和可用曲库类别数量，
  服务可能计费。不上传视频、画面、音乐文件或音乐路径。
- 模型以真实对白句段索引定位情绪和配乐提示段，支持英文对白及中文或英文剧本说明；
  没有对应时间的剧情或低置信对齐会报错，不能当作精确画面理解或逐拍卡点。
- 本地仍只从通过现有筛选的曲库选曲，参考剧情强度、减少重复，并保留原声和对白压低。
  “剧情留白”是计划明确的艺术选择，接口失败或缺曲不会伪装成留白。
- “转场必换曲”仍可使用，但不打断明确的剧情留白。关闭时，片段上限按实际有音乐的
  片段计数，留白不占上限；超过上限会提示调整，不丢弃剧情段。数量下限不足只警告，
  不会无依据地增加曲目补数。
- 更换文档内容、模型、接口地址或剧情模式后，会重新生成相关计划；其他参数或曲库
  变化仍可用“重新生成当前集”。这是独立项目的功能，不代表原项目已发布此功能。

- 保留词级转录时间，改进英文情绪线索、对白压低和换曲依据展示；增加时间轴跳转、句段试听、批次恢复与本机报告。

升级后请重新生成需要应用新规则的集数。旧成片不会自动变化；视觉规则仍可能误判或漏掉换场，情绪和纯音乐判断也需要抽查。

## 功能

- 批量扫描常见视频与音频格式，并按自然文件名排序。
- 按音乐目录分类和字幕/转录文本选择背景音乐。
- 支持整段 BGM 首尾淡入淡出，以及可开关、可调时长的曲目间交叉淡化。
- 支持对白时段降低 BGM 音量、片尾定格设置和多段配乐。
- 输出最终视频、BGM-only WAV、CSV 时间表、转录 JSON 和批次摘要。
- 支持断点续跑、单集失败后继续，以及 Electron 桌面界面。
- 可选使用 faster-whisper 在本机生成对白转录。
- 开始前显示目录、曲目数量、模型、输出内容和媒体组件检查；刷新窗口可恢复正在运行的批次与最近日志。
- 显示整体进度、当前处理阶段与估算剩余时间；运行事件不会重建审阅播放器或正在编辑的输入框。
- 队列支持集数搜索、状态筛选、仅重试失败项、继续未完成，以及重新生成当前集。
- 音乐库健康检查会提示空情绪目录、内容重复、不可解码、过短及近似静音曲目，不会删除素材。
- 默认严格纯音乐筛选：本地 YAMNet 滚动覆盖整首曲目，疑似人声、未确定和分析失败曲目不进入自动候选池。可搜索疑似区间试听、人工确认或禁用，并保存入点与强度。
- 保留词级对白时间，用 FFmpeg 镜头候选与停顿辅助定位；相邻同类片段合并，证据不足时沿用原曲或选择已筛选的相近、较克制曲目；没有合格候选时明确报错。留白仅用于明确的剧情意图。
- 时间轴和对白句段可点击跳转，支持成片 / 纯 BGM 切换、句段试听、播放指针和键盘控制。
- 提供四个配置预设、拖放导入、每类最近五个路径，以及预览后复制的脱敏诊断信息。
- 每次批次生成 `run-report.md` 与 `run-errors.log`，列出完成、跳过、失败、中断、未处理及实际存在的产物。
- Windows 正式安装版发现新版本时显示提醒，也可在“关于”页检查、下载并确认重启安装 GitHub Releases 中的新版本；开发模式不会联网检查。

## 获取 Windows 应用

从 [GitHub Releases](https://github.com/yuyuyu-a/auto-bgm/releases/latest) 下载 Windows 安装包并运行。v1.0.7 的安装包名称为 `auto-bgm-setup-1.0.7.exe`，内含 FFmpeg、faster-whisper small 和 YAMNet，媒体处理可以离线完成。便携版或其他平台目前没有发布。

旧版首次启用应用内更新时，需要先手动安装包含更新器的引导版；后续版本可在“关于”页完成检查、下载和重启安装。更新使用 GitHub Releases，网络不可用时不影响本地配乐功能。

首次使用：选择视频目录、按情绪分类的音乐目录和独立输出目录，先运行“整库人声筛选”，再设置每集至少使用的不同曲目数与“转场必换曲”，最后开始批次。疑似人声和不确定曲目默认不参与选曲，可按疑似区间短听后人工确认。升级已有项目时，可用“重新生成当前集”，或关闭“跳过已完成”后批量重配。

## 从源码运行

需要 Windows、Node.js 22.12 或更高版本，以及可从 `PATH` 调用的 FFmpeg 和 ffprobe。

```powershell
npm ci
npm test
npm run test:desktop-ui
npm run desktop
```

构建后的程序统一位于 `release/win-unpacked/自动配乐.exe`，保留完整目录后双击运行。只需本机预览时执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-windows.ps1 -Preview`，预览关闭自动更新；正式安装包构建见下文。

也可使用命令行：

```powershell
node src/cli.js `
  --videos "C:\Media\Episodes" `
  --music "C:\Media\BGM" `
  --output "C:\Media\Output" `
  --mood "默认"
```

目录参数需替换为你自己的素材位置。首次运行会要求你在应用中选择目录；程序不会把视频或音乐上传到网络。

命令行默认也采用严格筛选，读取桌面版建立的曲库缓存。初次全库人声分析使用桌面版“整库人声筛选”；Node 命令行没有 Electron 音频推理组件，未分析曲目不会被静默放行。明确接受未确认曲目时可加 `--allow-unverified-music`；人工禁用仍然生效。对白压低默认开启，`--no-auto-duck` 可关闭。

桌面交互回归使用隔离的临时配置、60 集模拟队列与实际生成的 WebM / WAV，不会读取你的素材；截图保存在 `build/ux-verification/`。

## 批次恢复与审阅

“继续未完成”会核验并跳过有效的已完成产物；“仅重试失败项”只处理当前输入中状态为失败的视频。“重新生成当前集”会先说明替换范围。这三个恢复入口始终保留对同名手工文件的保护。即使开启覆盖，也会阻止输出覆盖当前输入视频或音乐；建议使用独立输出目录。“新建批次”只清空界面配置，确认提示会说明磁盘文件保留。

点击时间轴音乐块可查看曲目与选曲原因，点击对白块或转录句段可跳到对应时间。在“成片”与“纯 BGM”间切换后，句段试听会使用当前来源。在播放快捷键区域使用空格播放 / 暂停、左右方向键跳转 5 秒；输入框和原生播放器保留自身键盘行为。宽屏右侧审阅栏独立滚动，宽度不超过 1000 像素时恢复普通页面滚动。

快速预览与纯配乐预设关闭转录，仅输出音频和时间轴；标准交付输出全部类型；对白优先同时开启转录和更强的对白压低。预设不会更改目录或开启覆盖。路径输入框可展开最近记录，也可直接拖入对应目录；空目录会自动识别为输出目录，含多种素材的目录可拖到指定路径栏。

预计剩余时间按本次实际完成集数的平均耗时估算，没有样本时显示“正在估算”。音乐库近似静音检查抽取曲目中间最多 5 秒，以平均音量不高于 -70 dB 为界；不足 2 秒和内容重复仅提示。自动转录、规则情绪判断及配乐结果仍需人工试听确认。

诊断信息只包含版本、运行时、工具可用性、模型大小、路径是否已配置、已列出的参数与错误类别；不复制私人路径、素材文件名、转录文本或原始错误日志。本机批次报告和错误日志用于交付及排错，保留产物路径和错误详情，分享前请自行检查其中的素材信息。

## BGM 目录

可把音频放在情绪子目录中；直接放在根目录的曲目会归为“默认”。
支持扫描多层子目录：普通专辑或合集目录继承上层分类；遇到软件已有情绪名称或别名（如“紧张”“悬疑”“悲伤”）时，该目录及其子目录使用这个分类。没有明确情绪标签时沿用第一层自定义分类，不会自动听音乐判断情绪。

```text
BGM/
  默认/calm.mp3
  悬疑/mystery.mp3
  紧张/action.wav
  紧张/专辑/第二辑/chase.wav
  音乐合集/伤感/钢琴/piano.mp3
```

上例中 `chase.wav` 归为“紧张”，`piano.mp3` 归为“伤感”。支持直接选择最外层曲库，不需要搬动或重命名音乐。目录符号链接、Windows 目录联接及文件符号链接不会扫描，以避免重复、循环和读取曲库外的文件。

支持 `.wav`、`.mp3`、`.m4a`、`.aac`、`.flac`、`.ogg` 和 `.opus`。

## 曲目衔接淡入淡出

在“设置”页面开启或关闭曲目切换时的交叉淡化，并填写过渡时长。默认开启，时长为 1 秒：上一段 BGM 淡出时，下一段同时淡入。时长不会超过较短配乐片段的一半。关闭后，曲目按原有方式直接切换。工作台中的“淡入时长”和“淡出时长”仍独立控制整段 BGM 的开头和结尾。

“设置 → 换曲与衔接”提供“转场必换曲”开关，默认开启。开启时，检测出的场景转场必须换成另一首，同时保留持续的对白情绪变化换曲；必换点不受约 12 秒间隔限制，片段数量上限暂停生效。关闭后恢复片段上限，主要按持续的对白情绪变化换曲。场景转场仍按强画面变化或黑场识别，普通切镜候选不逐个强制换曲。必换点没有另一首匹配情绪或兼容中性的合格音乐时，会明确报错并提示补充曲目。

每集下限按不同曲目计数，默认至少 1 首，关闭转场必换时默认最多 3 段。下限独立于转场开关：优先利用镜头变化，其次是对白停顿，仍不足时按可用时长补足；补足片段至少 6 秒，必换点可产生更短片段。同一首反复播放不计为多首；只使用匹配情绪或兼容中性的合格音乐。时长、必换点分段或候选不足时，队列、时间轴和批次报告会明确提示“未达到每集至少…首”。修改设置后重配当前集，或关闭“跳过已完成”后重新运行。

本地版本的“每集 BGM 数量”现在提供“不限制 / 自定义”模式。选择“自定义”会关闭与有限上限冲突的“转场必换曲”，可直接填写 5、17、100 等整数，不局限于固定选项；下限不能高于有效上限。选择“不限制”或输入 0 表示不限制片段数。重新开启“转场必换曲”时，界面回到不限制模式。设置在本机保存，重启后仍保留。这里限制的是每集配乐片段数量，不限制曲库曲目数；剧情留白不占配乐片段上限。

“设置”页面的“跳过已完成”默认开启。已有产物仍然有效时，批次会直接跳过对应集数；调整 BGM 或选曲参数后，关闭此开关即可重新生成已完成集数。关闭“允许覆盖已有结果”时仍会保护不属于程序的同名文件。

中文和英文台词支持常见情绪短语与否定表达；wedding、marry、love 等话题词和歧义医疗词不单独构成情绪证据。仅在有效词级时间存在时按标点、`but` 等真实词边界拆句；旧句段时间格式完整保留，不按字数估算。规则对隐喻、反讽和复杂剧情的理解有限。

曲库确认、禁用、分析与健康缓存保存在 `%USERPROFILE%/.bgm-studio/music-library/`，按曲库路径分开，按文件大小和修改时间失效。模型、设置版本变化会重算机器分析；人工确认在文件变化后失效，禁用保留。扫描可停止，已完成结果即时保存；扫描不生成长期 WAV。机器分数不是校准置信度，严格门槛可能误剔除纯音乐，不需要逐一听完所有歌曲，可按疑似区间复核。切勿仅凭曲名或未识别到文字确认无人声。

时间轴与批次状态记录分析版本、人声状态、入点、强度、词/句段时间来源、镜头候选、待检查原因和实际对白压低设置。音乐先归一响度，再对白压低与淡化。原视频音轨保留；原片已有音乐时仍可能与新 BGM 叠加，本轮不加入音乐分离。未开启“剧情辅助”时仍按本地文本规则判断情绪。

## 字幕与本机转录

字幕 sidecar 为与视频同名的 JSON 文件，例如 `transcripts/episode-01.json`：

```json
{
  "segments": [
    { "start": 12.4, "end": 15.8, "text": "危险，快跑" }
  ]
}
```

```powershell
node src/cli.js --videos "C:\Media\Episodes" --music "C:\Media\BGM" --output "C:\Media\Output" --transcripts "C:\Media\Transcripts"
```

要启用 faster-whisper 转录，安装 Python 依赖并提供本机模型目录：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:FASTER_WHISPER_MODEL = "C:\Models\faster-whisper-small"
node src/cli.js --videos "C:\Media\Episodes" --music "C:\Media\BGM" --output "C:\Media\Output" --transcribe
```

也可将 `FASTER_WHISPER_MODEL` 设为模型名称（例如 `small`），让 faster-whisper 从其配置的模型缓存中读取。转录与媒体处理在本机执行；首次获取模型可能需要网络。

## 构建 Windows 安装包

仓库内含固定版本的 faster-whisper small 模型包，位于 `models/`，约 425 MiB。模型归档拆成多个小于 45 MB 的源码文件，以便普通 GitHub 源码下载；构建脚本会自动重组、解压并验证模型文件的 SHA-256。无需额外下载模型。若要使用另一份本机模型，可选设置 `FASTER_WHISPER_MODEL` 覆盖默认模型。

需要 Windows、Node.js 22.12 或更高版本、Python、项目依赖及可用网络。构建脚本会校验并下载固定版本的 FFmpeg 和 4.13MB YAMNet 模型；`npm ci` 安装 Electron 与 MediaPipe Tasks Audio 1.2.2。沿用现有 Whisper 模型，不额外引入完整 TensorFlow/PyTorch。

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
npm run dist:win
```

构建产物写入 `release/`，包括安装包 `auto-bgm-setup-<版本>.exe`、对应 `.blockmap`、自动更新元数据 `latest.yml` 和 `win-unpacked/`。构建本身不会发布；发布 GitHub Release 时需要同时上传安装包、对应 `.blockmap` 和 `latest.yml`，保留三者的版本、文件名和 SHA-512 一致。安装包内的 `resources/licenses/` 包含第三方许可说明。模型来源和第三方许可证见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 与 [models/README.md](models/README.md)。

## 已知边界

- 规则模式使用关键词，不理解完整剧情；剧情辅助模式依赖剧本与真实对白的文本分析，
  不代表看过成片画面，不自动评估音乐艺术质量，均需试听。
- ASR 文本可能有误；请检查时间轴、对白清晰度、切点和最终成片。
- 仅在 Windows 环境测试和提供安装程序；没有承诺其他操作系统兼容性。
- 使用者需确保拥有输入视频和背景音乐的处理、复制及发布权利。
